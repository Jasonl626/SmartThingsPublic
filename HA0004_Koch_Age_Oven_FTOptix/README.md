# HA0004 Koch Age Oven — FactoryTalk Optix Migration

New FactoryTalk Optix project for the Koch age oven HMI, replacing the
FactoryTalk View ME v8.00 PanelView application
(`../HA0004_Koch_Age_Oven_v800_20250512.mer`, source in
`../HA0004_Koch_Age_Oven/`). The headline change is **improved data
logging**.

## Contents

| File | Purpose |
|------|---------|
| `HA0004_Koch_Age_Oven_FTOptix.optix` | Project file / entry point |
| `ProjectFiles/CommDrivers.xml` | RA EtherNet/IP driver replacing the `[Aging_Furnace]` FT Linx shortcut |
| `ProjectFiles/ModelTags.xml` | Model tag definitions mapped to the existing PLC UDTs |
| `ProjectFiles/DataLogger.xml` | The two new data loggers (see below) |

## Data logging design

The old ME project had a single data log model (`Age Oven flame
intensity`) sampling 8 tags into proprietary `.dat` log sets. The new
design has two loggers writing to an embedded SQL database
(`AgeOvenLogs`):

1. **AgeOvenProcessLog** — 10 s period, 365-day retention. The original
   8 tags (Loop 1/2 PV, target SP, working output; Z1/Z2 flame-safety
   signal strength) **plus** the previously unlogged hi-limit PVs and
   trip status, fan run status (Z1/Z2 combustion + recirc, exhaust),
   and production context (skid part count, oven state, active fault)
   so every logged sample is traceable to a run.
2. **FlameSafetyFastLog** — 1 s period, 30-day retention. Flame signal
   strength and burner outputs only, for troubleshooting intermittent
   flame-safety trips without bloating the main table.

Both tables store timestamp and quality per sample and are directly
SQL-queryable (and exportable to CSV from the runtime), replacing the
DAT-file workflow.

## Finishing the project in FactoryTalk Optix Studio

This folder is the configuration scaffold; the canonical Optix
serialization must be generated by FactoryTalk Optix Studio:

1. Create/open the project in Optix Studio (1.6+) and let it
   regenerate its serialization; use the XML files here as the
   definition of record for driver, tags, and loggers.
2. Set the real PLC IP address in the `Aging_Furnace` station
   (placeholder is `192.168.1.10`).
3. **Verify the tag paths marked `NEW` in the CSV against the actual
   ControlLogix program** — the original 8 log tags are taken verbatim
   from the ME data log model, but the added UDT member names
   (`.Tripped`, `.Running`, `SKID_PART_COUNT`, `OVEN_STATE`,
   `SYSTEM_FAULT_ACTIVE`) are inferred from the ME parameter files and
   must be confirmed in Studio 5000 before deployment.
4. Rebuild the display set (FurnaceMain, trend screens, soak data,
   quality, maintenance) — screen migration is not covered by this
   scaffold.
5. Point the trend objects at `AgeOvenProcessLog` /
   `FlameSafetyFastLog` instead of the old log model.

## Deployment target

The old app ran on a PanelView Plus. FTOptix runtime targets:
OptixPanel, a PC runtime, or a PanelView Plus 7 (with FTOptix
firmware). Confirm the target before sizing the retention windows —
365 days at 10 s × 20 tags is modest (~65 MB/yr as SQLite) but the
panel's storage should be checked.
